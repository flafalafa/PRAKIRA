# T-705: API Peringatan dan Notifikasi Enterprise (Enterprise Notification & Alert API)

## Ringkasan
Berhasil mengimplementasikan **Enterprise Notification & Alert API**. Modul ini adalah saluran komunikasi transparan yang memungkinkan warga desa atau institusi untuk melihat riwayat peringatan banjir dan melacak apakah pesan tersebut berhasil dikirim oleh infrastruktur kita.

## Keputusan Arsitektur
1. **Pemisahan Entitas Alert & Delivery (Krusial)**: 
   API ini menegaskan batas filosofis sistem:
   - **Alert (Peringatan)**: Murni mewakili kondisi bahaya di lapangan (misal: Tanggul Jebol = Status ACTIVE, EMERGENCY).
   - **Notification (Pengiriman)**: Mewakili status kurir pesan ke perangkat pengguna (misal: Firebase Timeout = FAILED).
   Jika notifikasi gagal terkirim (karena kuota FCM habis), sistem API **TIDAK AKAN** mengubah status Alert menjadi tidak bahaya. 
2. **Read-Only / Adaptor Murni**: Sesuai perintah SDS, API ini secara ketat dilarang untuk memicu pengiriman pesan FCM, mengurus deduplikasi, atau mengatur siklus pendinginan (*Cooldown*). Semua itu adalah tugas Mesin Notifikasi (Sprint 6). API Layer ini hanyalah "Kaca Pembesar" untuk membaca catatan yang ditinggalkan oleh Mesin Notifikasi.
3. **Privasi Tingkat Pengguna**:
   - Rute `/alerts/active` bersifat terbuka (Sesuai kebijakan rute T-702, ia hanya butuh otentikasi standar, namun siapa saja warga bisa melihat peringatan publik suatu area).
   - Rute `/notifications` mengaktifkan filter tingkat baris (*Row-level filtering*). Sistem mengecek parameter `user.principal_id`. Seorang pengguna tidak akan bisa meretas API untuk melihat riwayat notifikasi tetangganya.
4. **Penyembunyian Rahasia Infrastruktur**: DTO `NotificationDeliveryStatus` sengaja dirancang untuk merangkum status kegagalan ("FCM timeout"), namun TIDAK PERNAH membocorkan `Device Token`, `API Key FCM`, atau muatan internal JSON ke jaringan publik HTTP.
