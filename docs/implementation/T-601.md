# T-601: Fondasi Notifikasi Enterprise (Enterprise Notification Foundation)

## Ringkasan
Berhasil mengimplementasikan **Enterprise Notification Foundation**. Ini adalah batu pijakan pertama untuk Sprint 6. Modul ini bertugas menerima "Dokumen Prediksi" dari *Decision Engine* dan mengubahnya menjadi format amplop pengiriman standar (`NotificationRequest`) yang siap disebarkan ke berbagai jalur komunikasi (Push, WhatsApp, Telegram, dll) tanpa membocorkan kerumitan logika hidrologi/radar ke lapisan pengiriman.

## Keputusan Arsitektur
1. **Agnostik Terhadap Provider (Provider Independent)**: Modul ini murni fondasi struktural. Ia **TIDAK** berisi logika untuk menghubungi Firebase, Twilio, atau WhatsApp. Dengan pola ini, jika tahun depan kita pindah dari FCM (Firebase) ke sistem Push Notification buatan sendiri, *core logic* notifikasi kita tidak perlu diubah sedikit pun.
2. **Abstraksi Saluran (`BaseNotificationChannel`)**: Semua jalur pengiriman (misal: SMS, WA) kelak diwajibkan untuk mengadopsi kontrak fungsi `send(NotificationRequest) -> DeliveryStatus`. Pola *Interface* ini menjamin keseragaman dan stabilitas (*Dependency Inversion Principle*).
3. **Konversi Prioritas Otomatis (`NotificationBuilder`)**: Tidak semua pemberitahuan itu sama. Prediksi bersatus `WATCH` akan diberi prioritas pengiriman `NORMAL`. Namun, prediksi berstatus `EMERGENCY` (Evakuasi segera) akan di-tag sebagai `CRITICAL/EMERGENCY` sehingga kelak *channel* pengiriman bisa memanfaatkan fitur *bypass do-not-disturb* (DND) di ponsel warga.
4. **Registri Saluran Dinamis (`ChannelRegistry`)**: Seperti halnya arsitektur Orkestrator, *channel* notifikasi dikelola melalui *Registry*. Ini memungkinkan kita mematikan saluran SMS (misalnya karena kuota API habis) tanpa harus mematikan *server*.

## Batasan yang Diketahui
- `NotificationManager` saat ini hanya berupa rangka (placeholder) yang hanya melakukan logging tanpa mengirim apa-apa, karena *Channel* pengiriman (seperti *Firebase Cloud Messaging*) baru akan diimplementasikan pada tugas-tugas berikutnya.
- Fitur templat pesan (*message templating*) masih merujuk langsung ke penjelasan bawaan (*explanation*) tanpa dukungan mesin lokalisasi (*i18n*).

## Peningkatan Kedepan
- **Multi-language Templating**: Menambahkan mesin templat dinamis (seperti Jinja2) di dalam *Builder* untuk merender pesan peringatan spesifik ke dalam bahasa Indonesia dan Inggris secara bersamaan (tergantung preferensi aplikasi penerima).
- **Rich Notification Attachments**: Menambahkan atribut lampiran (*attachments*) pada `NotificationRequest` sehingga kelak kita bisa mengirimkan peta evakuasi (gambar) atau cuplikan radar cuaca sebagai bagian dari notifikasi Push.
