# T-201: Enterprise Persistence Foundation

## Summary
Successfully established the enterprise persistence layer for Flood Guardian (Sprint 2). This foundation embraces modern SQLAlchemy 2.0 asynchronous patterns (`AsyncEngine`, `AsyncSession`) without coupling to any specific business entities. It prepares the application for Alembic migrations, PostgreSQL integration, and future PostGIS spatial capabilities.

## Architecture Decisions
1. **Centralized Metadata & Naming (`metadata.py`, `naming.py`)**: By injecting a strict `NAMING_CONVENTION` into the SQLAlchemy `MetaData`, all constraints (Foreign Keys, Indexes, Unique constraints) generated by Alembic will follow a predictable naming pattern. This prevents `ValueError: Constraint must have a name` errors during database migrations.
2. **SQLAlchemy 2.0 Native (`base.py`)**: Migrated away from the legacy `declarative_base()` in favor of the modern `DeclarativeBase` class approach.
3. **Lazy Engine Initialization (`engine.py`)**: The `DatabaseEngineManager` does not spawn connection pools at import time. The engine is strictly initialized lazily. If `settings.database.uri` is empty, it elegantly falls back to `sqlite+aiosqlite:///:memory:` to ensure unit tests can run safely without spinning up Docker.
4. **Context-Managed Sessions (`session.py`)**: Created an asynchronous context manager `get_db_session()`. This isolates transaction boundaries, enforcing a strict try-commit-except-rollback lifecycle, preventing connection leaks.
5. **Types Registry (`types.py`)**: Unified standard field lengths (e.g. `STRING_MEDIUM = String(255)`) and provided placeholders for JSONB and PostGIS geometries to ensure database agnostic types where possible.

## Known Limitations
- The connection pooling arguments (`pool_size`, `max_overflow`, `pool_pre_ping`) are only applied if the URL explicitly starts with `postgresql`. SQLite in-memory ignores these pooling parameters.

## Future Improvements
- **Alembic Integration (T-202)**: The `metadata.py` and `registry.py` will be imported directly by Alembic's `env.py` to support autogenerating migration scripts.
- **Dependency Injection**: The `get_db_session()` will be wired into `backend/app/core/providers.py` in future tasks, allowing `DatabaseProvider` to supply FastAPI with scoped transactions via `Depends()`.
