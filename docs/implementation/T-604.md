# T-604: Penyedia Layanan Notifikasi Push (Enterprise Push Notification Provider)

## Ringkasan
Berhasil mengimplementasikan **Enterprise Push Notification Provider**. Modul ini adalah "Pasukan Eksekutor" yang bertugas mengantarkan pesan langsung ke layar ponsel pintar warga. Modul ini menjembatani jarak antara logika internal aplikasi kita dengan *API Server* pihak ketiga seperti **Firebase Cloud Messaging (FCM)**.

## Keputusan Arsitektur
1. **Desain Abstraksi Murni (*Provider Interface*)**: Logika pengiriman FCM (Google) benar-benar diisolasi di dalam sub-folder `providers/fcm/`. Sistem inti (*Orchestrator* atau *Scheduler*) sama sekali tidak tahu bahwa kita menggunakan FCM. Jika esok hari pemerintah mewajibkan kita menggunakan layanan Push Notifikasi milik Kominfo, kita cukup membuat folder `providers/kominfo/` tanpa merusak satupun baris kode di sistem inti.
2. **Pemetaan Kasta Prioritas (*Priority Mapping*)**: Di T-601 kita mendefinisikan prioritas pesan internal (seperti `EMERGENCY`). Di modul ini (`FCMMapper`), prioritas tersebut diterjemahkan secara harfiah ke dalam struktur *Payload Android*. Pesan darurat akan memicu flag `"android": {"priority": "high"}`, yang secara teknis akan memaksa sistem operasi Android untuk membangunkan ponsel dari mode tidur lelap (*Doze Mode*) dan menampilkan pesan saat itu juga.
3. **Validasi Sebelum Terbang (*Pre-flight Validation*)**: FCM membatasi ukuran *payload* data maksimal 4KB (4096 bytes). `FCMValidator` akan mencegat dan menghitung ukuran byte dari pesan sebelum dikirim. Jika pesan terlalu panjang, ia akan langsung diblokir di *server* kita agar tidak membuang-buang *bandwidth* untuk pengiriman yang pasti akan ditolak oleh Google.
4. **Pemeriksaan Kesehatan (*Health Check*)**: Modul dilengkapi kemampuan untuk memeriksa status koneksinya ke server Google secara berkala (*Latency* dan Status Otentikasi).

## Batasan yang Diketahui
- `FCMClient` saat ini masih berupa simulasi API (Mock) dengan penundaan waktu *asyncio.sleep(0.1)*. Integrasi otentikasi nyata menggunakan `firebase-admin` SDK belum di-install.
- Sistem saat ini hanya dirancang untuk *Single Device Token*. Pengiriman *Topic* (Broadcast masal ke seluruh Kelurahan) akan diimplementasikan pada fase optimasi.

## Peningkatan Kedepan
- **FCM Topic Messaging**: Alih-alih mengirim pesan satu-satu ke 5.000 warga Pondok Aren (menguras CPU), kita akan memanfaatkan fitur *Topic* FCM (`/topics/pondok_aren`), sehingga kita hanya memanggil API Google 1 kali, dan Google yang akan melakukan distribusi ke 5.000 perangkat tersebut.
- **Apple Push Notification (APNs)**: Menambahkan modul `providers/apns/` khusus untuk melayani warga yang menggunakan perangkat iPhone/iOS.
