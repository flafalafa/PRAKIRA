# T-106: Enterprise Middleware Foundation

## Summary
Successfully implemented a robust, centralized middleware architecture for Flood Guardian. By establishing a central `Middleware Registry`, the application factory is now decoupled from middleware instantiation logic. The execution order is deterministic, ensuring requests pass through strict security, tracing, and performance layers before reaching the routing logic.

## Architecture Decisions
1. **Centralized Registry (`registry.py`)**: Moved all `app.add_middleware()` calls into a dedicated registry. Due to FastAPI/Starlette's LIFO (Last-In-First-Out) behavior for middleware registration, middlewares are deliberately added in **reverse execution order** (from innermost to outermost). 
2. **Context Passing**: Designed the architecture so that the `RequestIDMiddleware` sits on the outermost edge to generate the `X-Request-ID`. This ensures that downstream layers like `RequestLoggingMiddleware` have immediate access to `request.state.request_id`.
3. **Configuration Driven**: Security headers (`X-Frame-Options`, `Content-Security-Policy`, etc) and Performance thresholds (e.g. `slow_request_threshold_ms`) are loaded directly from `settings.py`, eliminating hardcoded values and allowing `production` environments to enforce stricter rules purely through `.env`.
4. **Maintenance Switch**: Included a `MaintenanceModeMiddleware` bound to a feature flag (`ENABLE_MAINTENANCE_MODE`). It gracefully intercepts all routes except `/api/v1/health` with a 503 response, guaranteeing safe maintenance windows without causing internal app errors or terminating the Uvicorn worker.

## Middleware Execution Flow
1. **Request ID** *(Outermost)*: Assigns trace ID.
2. **Correlation ID & Logging**: Initializes JSON logger context.
3. **Trusted Host**: Rejects bad Host headers.
4. **Security Headers**: Injects OWASP standard headers.
5. **CORS**: Handles pre-flight OPTIONS and origin checks.
6. **GZip**: Compresses payloads over 1000 bytes.
7. **Performance Metrics**: Timers and threshold alerts.
8. **Maintenance Mode** *(Innermost)*: Immediate 503 if flagged.
9. *[Router]*

## Known Limitations
- Performance tracking is currently limited to pure request duration (`time.time()`). Gathering accurate CPU usage per-request or tracking memory deltas reliably in Python requires either `psutil` or an APM/profiler, which falls outside the current infrastructure boundaries.

## Future Improvements
- **Authentication/Authorization Middlewares**: Ready to be injected into the registry between *CORS* and *Performance*.
- **Rate Limiting**: Can be integrated alongside Redis in Sprint 4.
