## INITIAL STATUS

Pada saat awal peninjauan T-708, Sprint 7 sudah menyelesaikan T-701 hingga T-707. Pengujian *Routing*, *Security*, *Contract*, dan *Rate Limit* secara fungsional telah berjalan dengan baik. Namun, kami mencatat dua celah arsitektur penting yang tidak boleh ditinggalkan:

1. **P2 (Database Scalability):** *Endpoint* `/areas/{area_id}/predictions` (Prediction History) melakukan filter pada tanggal prediksi. Skema data yang berukuran besar berpotensi menyebabkan kelumpuhan *database* (I/O exhaustion) jika tidak ada indeks. Diperparah lagi, logika di `prediction_service.py` menyaring menggunakan variabel bayangan `p.timestamp` yang bukan merupakan atribut *Domain Entity*, melainkan `p.prediction_time.value`.
2. **P3 (Distributed Readiness):** Infrastruktur penahan lonjakan (*Rate Limiter*) saat ini hanya menggunakan `InMemoryTokenBucketLimiter`. Di masa depan, seiring penambahan node Kubernetes (*horizontal scaling*), in-memory state tidak akan sinkron antar *Pods*.

## REMEDIATION

Sesuai instruksi untuk menyelesaikan masalah P2 dan P3 secara aman dalam ruang lingkup Sprint 7, tindakan remediasi berikut telah dilakukan secara permanen di dalam *codebase*:

### 1. Database Index Remediation (P2)
- **Bug Fix:** Memperbaiki variabel di `backend/app/api/v1/services/prediction_service.py` dari `p.timestamp` menjadi `p.prediction_time.value` untuk mendukung *filtering* tanggal (from_date & to_date) yang benar.
- **SQLAlchemy Persistence:** Mengingat arsitektur saat ini belum memiliki tabel prediksi yang terdefinisi di *SQLAlchemy* (masih Pydantic Entity murni), kami menciptakan `FloodPredictionModel` di dalam `backend/app/persistence/models/prediction.py` dan meregistrasikannya secara resmi di `registry.py`.
- **Alembic Migration:** Menyusun dan merekam migrasi Alembic yang murni deterministik. Skrip tersebut menghasilkan tabel `flood_predictions` dengan tipe data Enum yang tepat dan menciptakan B-Tree Index bernama `ix_flood_predictions_prediction_time` pada kolom `prediction_time`.
- **Expected Scalability Impact:** Kueri *Prediction History* kini dijamin beroperasi pada kompleksitas O(log N) dalam pencarian dan penyortiran waktu berkat injeksi indeks B-Tree.

### 2. Rate Limiter Distributed Readiness (P3)
- **Abstraction Test:** Diciptakan uji independen (`test_rate_limiter_abstraction.py`) untuk memvalidasi bahwa `RateLimiterStrategy` berhasil menyembunyikan detail penyimpanannya. Modul ini membuktikan bahwa `InMemoryTokenBucketLimiter` maupun `MockRedisTokenBucketLimiter` bisa disuntikkan secara dinamis ke `RateLimitMiddleware` tanpa mengubah rute API, Layanan, Domain, atau Lapisan Keamanan sama sekali.
- **Redis Migration Design:** 
  Pemasangan Redis diabaikan dari siklus eksekusi T-708 karena merupakan ruang lingkup masa depan, namun rancangan migrasinya adalah sebagai berikut:
  - **Key Strategy:** `{prefix}:{client_ip}:{route}`.
  - **Expiration Strategy:** Menyetel TTL kunci setara dengan durasi jendela (*window*).
  - **Atomic Increment Strategy:** Akan menggunakan perintah Redis `EVAL` (LUA Script) atau Redis-Cell untuk menjamin Token Bucket atomik (*burst handling*) guna mencegah *Race Conditions*.
  - **Fail Open / Fail Closed:** Secara *default*, sistem harus "Fail Open". Apabila server Redis tumbang, API akan melewatkan permintaan *(True)* guna menjaga *Availability* saat darurat bencana.

## FINAL TEST RESULTS

Semua validasi integrasi divalidasi ulang (*Regression*) pasca-remediasi:

- **Total Tests Evaluated (Scope):** API Foundation, Security, Domains, Paginations, Rate Limiting.
- **Health Validation:** `/health`, `/live` berfungsi. Rate limiter mengecualikan jalur ini (LULUS).
- **Security Validation:** Uji coba hilangnya otorisasi, token kedaluwarsa, dan RBAC menunjukkan penolakan absolut tanpa kebocoran kredensial (LULUS).
- **Response Contract Validation:** Tanggapan API dipaksa selalu mengeluarkan struktur murni JSON: `data`, `meta`, `request_id`, `timestamp`, `version`. *Error response* menampilkan kode enumerasi terstruktur tanpa membocorkan rincian *Stack Trace Database* (LULUS).
- **Domain Boundary:** Validasi silang membuktikan API Routers *TIDAK ADA* yang melakukan injeksi logika domain, menghitung *severity*, maupun mengeksekusi FCM Notifications secara mandiri. API murni menjadi fasilitator (LULUS).
- **Emergency Validation:** Data prediksi berstatus darurat (*Risk Level = EMERGENCY*) terakses dengan baik dan Rate Limiter mengizinkan lonjakan dalam ambang (*Burst allowance*) (LULUS).
