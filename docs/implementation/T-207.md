# T-207: Enterprise Unit of Work Framework

## Summary
Successfully implemented the `Enterprise Unit of Work (UoW) Framework`. This pattern resolves the critical issue of synchronizing multiple Repositories across a single Database Transaction boundary. The UoW ensures that if a Business Workflow requires writing to 3 different tables (e.g. creating a `User`, assigning an `Area`, and logging an `Audit`), they all succeed together, or they all roll back together (Atomicity).

## Architecture Decisions
1. **Explicit Transaction Lifecycle (`base.py`)**: The `BaseUnitOfWork` utilizes Python's asynchronous context managers (`__aenter__` and `__aexit__`). It automatically initializes an `AsyncSession` when entering the block, and implicitly rolls back the transaction if any unhandled `Exception` propagates out of the block.
2. **Explicit Commit Enforcement**: The framework does NOT use Auto-Commit. It requires the Domain Logic to explicitly call `await uow.commit()` upon success. If a service finishes its work but forgets to call commit, the changes are silently rolled back upon exiting the `async with` block, preventing unintended partial updates.
3. **Context Injection (`context.py`)**: By wrapping the UoW inside `contextvars`, deeply nested background tasks (like the `Decision Engine`) can retrieve the currently active UoW without having to pass it explicitly through ten layers of function signatures.
4. **FastAPI Integrations (`manager.py`)**: Provided `get_uow_dependency()` designed exclusively to be consumed by FastAPI's `Depends()` injection system.
5. **Observability**: UoW initialization, commitments, rollbacks, and unexpected exceptions are natively tracked by the Enterprise JSON Logger from T-104.

## Known Limitations
- Repositories (`self.users`, `self.rivers`, etc.) are currently just conceptual placeholders in `base.py` and `interfaces.py`. They cannot be fully integrated until Sprint 3 (Domain Modeling & Business Entities) commences.

## Future Improvements
- **Domain Event Dispatcher**: Once the business repositories are built, the UoW's `commit()` method will be enhanced to scan repositories for queued "Domain Events" and dispatch them automatically just before issuing the database commit, finalizing the Event-Driven Architecture outlined in the SDS.
