# T-801: Enterprise Flutter Mobile Application Foundation

## Executive Summary
Tugas T-801 merupakan fondasi pertama pengembangan sisi Klien (*Client-Side*) berupa aplikasi seluler **Flood Guardian** menggunakan Flutter. Kami telah menyiapkan arsitektur orientasi fitur (*feature-oriented architecture*), menetapkan abstraksi *Networking* dan *Storage*, serta mengonfigurasi batas-batas penanganan galat (*Error Boundaries*). Fokus utama T-801 murni pada peletakan **Arsitektur Dasar**, sehingga pengembangan logika bisnis tetap berada di Backend, dan Klien berfungsi sepenuhnya sebagai antarmuka yang mengonsumsi kontrak API dari T-706.

---

## Architecture Decisions
- **Monorepo Strategy:** Aplikasi Flutter ini ditempatkan pada direktori `mobile/` pada *monorepo* yang sama dengan Backend.
- **Client Constraint:** Flutter bertindak secara ketat sebagai **Klien Konsumen**. Seluruh pembuatan Prediksi, Kalkulasi Risiko, Peringatan Otomatis, dan kebijakan Eksekusi Notifikasi tetap berada dan dilindungi di sisi *Backend*.
- **Feature-Oriented Structure:** Mengisolasi dependensi antara fitur secara vertikal (Areas, Predictions, Alerts, Notifications).

## Bootstrap Flow
- Berkas `main.dart` bertanggung jawab menyatukan dependensi *Framework* dasar sebelum memulai injeksi *Widget*.
- Inisialisasi sentral: 
  1. `WidgetsFlutterBinding.ensureInitialized()`
  2. Inisialisasi `AppLogger`
  3. Mengambil ENV variabel (e.g. `development`, `staging`, `production`) dan memanggil `AppConfig.init()`
  4. Menyiapkan abstraksi penyimpanan (`StorageProvider.init()`)
  5. Bootstrap `runApp(FloodGuardianApp())`.

## Environment Configuration
Diimplementasikan pada `app_config.dart`.
- Mendukung pemisahan lingkungan dev, staging, dan prod.
- *Endpoint* API tidak boleh lagi di-hardcode ke dalam kode UI. Seluruh pemanggilan memanfaatkan `${AppConfig.apiBaseUrl}${AppConfig.apiVersion}` (seperti `/api/v1/`).

## Navigation
Diimplementasikan pada `router.dart`.
Mendefinisikan *Route Generator* sentral:
- `/` (home)
- `/areas`
- `/predictions`
- `/alerts`
- `/notifications`
- `/settings`
*Module UI dilarang melakukan instansiasi layar lain secara eksplisit melainkan menggunakan Route Name.*

## Network Foundation
Diimplementasikan pada `api_client.dart` (Berbasis `Dio`).
- Menjalankan koneksi HTTP, pengaturan *Connect Timeout* (15s) dan *Receive Timeout* (15s).
- Memastikan T-706 API Contract diikuti secara ketat.
- Menyuntikkan interseptor untuk Logging dan Identifikasi Permintaan HTTP (`X-Request-ID`).

## Storage Foundation
Diimplementasikan pada `storage_provider.dart`.
- `LocalStorage`: Abstraksi untuk kebutuhan pengaturan tema, *cache* tak krusial, ditenagai oleh `shared_preferences`.
- `SecureStorage`: Abstraksi penyimpanan rahasia ditenagai oleh `flutter_secure_storage`. Mengamankan JWT Access/Refresh tokens dengan enkripsi Keystore (Android) / Keychain (iOS).

## Error Handling
Diimplementasikan pada `failure.dart` dan dipetakan di `api_client.dart`.
- Memetakan respon API (400, 401, 403, 404, 422, 429, 500) ke turunan entitas `AppFailure` spesifik (mis. `ValidationFailure`, `RateLimitFailure`).
- Mencegah kebocoran jejak *stack* atau SQL ke publik. Antarmuka UI kelak hanya merender atribut `.message`.

## Security
- Kredensial *Backend*, *FCM Server Keys*, dan rahasia *Database* DILARANG Keras dimasukkan dalam direktori `mobile/`.
- Tidak ada token yang direkam ke log maupun dimasukkan dalam basis data tak terenkripsi.
- Autentikasi disiapkan menggunakan abstraksi *SecureStorage*.
