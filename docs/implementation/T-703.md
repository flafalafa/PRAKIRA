# T-703: API Area dan Lokasi Enterprise (Enterprise Area & Location API)

## Ringkasan
Berhasil mengimplementasikan **Enterprise Area & Location API**. Modul ini adalah jembatan bagi aplikasi eksternal (seperti Flutter atau Dashboard BPBD) untuk meminta katalog area yang saat ini dipantau oleh Flood Guardian beserta dengan metadata geografis (titik kordinat) mereka.

## Keputusan Arsitektur
1. **Penggunaan Kembali Entitas Domain (*Domain Entity Reuse*)**: Modul ini sepenuhnya mematuhi prinsip Clean Architecture. API sama sekali tidak berani mendefinisikan ulang apa itu "Area". Ia mengimpor Entitas `Area` dan Value Object `Coordinate` murni peninggalan Sprint 3.
2. **Abstraksi Pola Repositori (*Repository Pattern*)**: Pengambilan data dari *database* tidak dilakukan dengan melempar query SQL mentah dari dalam *Router*. API berkomunikasi secara sopan menggunakan *Application Service* (`AreaApplicationService`), yang kemudian memanggil *Interface* Repositori (`AreaRepository`). 
3. **Pemisahan DTO (*Data Transfer Object Mapping*)**: Modul `AreaMapper` dibangun untuk memastikan struktur `Area` internal dikonversi menjadi `AreaResponse` bersih sebelum dilemparkan ke ranah publik. Ini menyembunyikan logika internal (misalnya properti SQLAlchemy) dari hadapan klien HTTP.
4. **Keamanan Bawaan (*Security Integration*)**: Semua Endpoint `/areas` diintegrasikan dengan modul T-702. Parameter `Depends(get_current_user)` disuntikkan secara otomatis. Tanpa JWT atau API Key yang valid, tidak ada satu pun data koordinat wilayah yang bisa diunduh.
5. **Dukungan Filter dan Paginasi (*Pagination Foundation*)**: Untuk mengantisipasi sistem memonitor 10.000 titik tanggul di masa depan, respons API telah dibatasi menggunakan fondasi paginasi dari T-701.

## Batasan yang Diketahui
- Untuk pengujian di *stub* ini, logika filtering (seperti pencarian teks `search`) diterapkan di memori (Python List). Dalam implementasi *production-ready* yang sesungguhnya (jika ORM PostgreSQL sudah aktif sepenuhnya), filter tersebut harus diturunkan (*push down*) ke kueri SQL Repositori untuk mencegah kebocoran memori.
- Pencarian Radius Geospasial (misal: "Cari sungai dalam radius 5km dari kordinat saya") belum diaktifkan karena PostGIS belum dikonfigurasi di infrastruktur ini.

## Peningkatan Kedepan
- Integrasi ke *Redis Cache* untuk memori sementara (Mengingat data koordinat wilayah jarang sekali berubah, melayani 1000 request per detik dari Flutter cukup menggunakan Cache tanpa menyentuh *database*).
- Menambahkan *Endpoint* pelaporan status cuaca oleh pengguna (*Crowdsourcing*).
