# T-404: Pengumpul Data Radar RainViewer (RainViewer Radar Collector)

## Ringkasan
Berhasil mengimplementasikan Modul Kolektor khusus Radar untuk penyedia RainViewer. Sesuai dengan spesifikasi tugas (T-404), modul ini dibangun semata-mata untuk mengumpulkan jejak citra radar (*radar imagery*) serta metadata pergerakan awan presipitasi, dan dengan patuh meneruskan standarisasi pipa data *Collector Foundation* (T-401). Hadirnya data radar spasial ini kelak akan melengkapi data sensor darat (BMKG/OpenWeather) untuk memberikan dimensi spasial (*spatial dimension*) kepada Mesin Prediksi.

## Keputusan Arsitektur
1. **Fokus pada Metadata Spasial**: API RainViewer memberikan puluhan tautan/url (berupa frame `past` dan `nowcast`). Kolektor ini tidak bertugas mengunduh gambar PNG mentah tersebut, melainkan mengekstraksi dan menormalisasi *metadata radar* (Timestamp, Host, Path URL) untuk dikemas secara rapi sebagai `NormalizedData` berparameter `radar_frame_past` dan `radar_frame_nowcast`.
2. **Pencegahan Duplikasi Frame (*Duplicate Frame Guard*)**: Karena API cuaca radar acapkali lamban dalam pembaruan (*refresh*), sangat mungkin mesin memanggil API yang sama dan mendapatkan hasil JSON berisi frame radar yang juga sama dengan menit sebelumnya. Modul `RainViewerValidator` dilengkapi logika himpunan `set()` untuk mengecek `timestamp` dan memveto penyerahan frame ganda (duplikat) agar tidak membuang-buang memori di Lapisan Domain nantinya.
3. **Pemisahan Entitas dan Kalkulasi**: Kolektor ini sangat "bodoh" secara kalkulatif, sesuai dengan pedoman yang diinstruksikan. Ia tidak berhak menghitung arah gerak badai (Storm Tracking), menghitung vektor gerak hujan, apalagi menerka waktu ketibaan banjir. Tanggung jawab berat tersebut sepenuhnya dipindahtangankan kepada *Radar Analysis Engine* / *Decision Engine* yang akan dibangun kelak.

## Siklus Request & Normalisasi
1. **Connect**: Membuka koneksi `httpx` *async* dengan jaminan *retry* dan *backoff* eksponensial (mengingat RainViewer terkadang merespon lambat).
2. **Fetch**: Memanggil titik henti `weather-maps.json` publik milik RainViewer untuk meraup indeks radar seluruh dunia yang paling mutakhir.
3. **Parse**: Membedah JSON mentah untuk menargetkan segmen khusus `"radar" -> "past"` (Histori Gerak) dan `"radar" -> "nowcast"` (Ramalan Gerak Pendek).
4. **Normalize**: Merakit `host` (Domain server RainViewer) dengan `path` (Jalur spesifik gambar per waktu) untuk membentuk URL tautan citra yang valid seutuhnya. Menanamkan resolusi baku *tile* (biasanya berukuran 256).

## Batasan yang Diketahui
- Kolektor saat ini membubuhi ID Area secara generik/global (`"area_id": "global"`) karena RainViewer menayangkan *tile* gambar untuk peta bumi (seluruh dunia). Pemotongan spesifik (*Cropping*) / penyesuaian radar untuk wilayah sasaran (misal: "Pondok Aren" / "Banten") akan diurus langsung oleh Layanan Pengolah Citra di tahap selanjutnya, bukan oleh Kolektor.

## Peningkatan Kedepan
- **Analisis Vektor Hujan (*Rain Cell Tracking*)**: Meskipun hari ini ditahan agar tidak diimplementasi, fondasi `radar_frames` yang tersusun kronologis (di modul *mapper*) sudah dipersiapkan sangat rapi. Kelak, Mesin Cerdas (Prediction Engine) dapat memutar rentetan bingkai radar ini, menggunakan *Computer Vision* (seperti deteksi *Optical Flow*), untuk menghitung arah dan waktu ketibaan awan badai (ETA) ke koordinat perumahan pengguna.
