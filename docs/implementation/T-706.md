# T-706: Enterprise API Response, Pagination & Error Contract

## Ringkasan
Berhasil mengimplementasikan standarisasi dan pengerasan kontrak API publik **(API Response & Error Contract)**. Modul ini menjamin bahwa seluruh *endpoint* REST API Flood Guardian, baik itu API Area, Prediksi, maupun Peringatan, berbicara dalam satu bahasa universal yang sama, baik ketika sukses maupun gagal.

## Keputusan Arsitektur
1. **Pelepasan Amplop "Error" (*Flattening Envelope*)**: Sesuai instruksi SDS terbaru, skema respons error diubah (didiratakan) agar atribut `request_id`, `timestamp`, dan `version` kini berada di lapis teratas (*top-level*), sejajar dengan `error_code` dan `message`. Ini membuat penguraian oleh klien (*Client Parsing*) di Flutter menjadi jauh lebih mudah tanpa harus mengakses objek *nested* berulang kali.
2. **Katalog Kode Kesalahan Stabil (*Error Code Catalog*)**: Alih-alih mengekspos teks Exception Python ke publik, semua error dilemparkan (*mapped*) ke enumerasi `ErrorCode` (misal: `AREA_NOT_FOUND`, `INVALID_COORDINATE`). Klien aplikasi cukup melakukan `switch-case` terhadap *string* stabil ini, tanpa perlu membedah kalimat pesan (`message`) yang bisa berubah-ubah bahasanya.
3. **Pemusatan Panangkap Error (*Global Exception Handler*)**: Tidak ada lagi blok `try-except` di dalam Router API. Saya mendirikan `error_handler.py` sentral di instansi aplikasi utama FastAPI. Ia menangkap:
   - Validasi Pydantic yang gagal (Diubah menjadi struktur HTTP 422 `VALIDATION_ERROR` dengan perincian per *field*).
   - `AppException` internal dari lapisan *Domain* (Dikonversi dari 404/403/500 berdasarkan instansiasi Exception).
   - Eksepsi HTTP standar (seperti memukul *endpoint* yang tidak ada).
   - *Unhandled Exception* tak terduga (diubah ke `INTERNAL_ERROR` 500, membunyikan alarm Log, tanpa membocorkan Stack Trace ke publik).
4. **Retrofit Seluruh Sprint 7**: Seluruh modul `areas.py`, `predictions.py`, `flood_status.py`, `alerts.py`, dan `notifications.py` telah ditulis ulang agar patuh secara mutlak terhadap skema baru melalui skrip Python otomatis (`refactor.py`).

## Kontrak Respons Standar Baru

**Berhasil (*Single Object*):**
```json
{
    "data": { ... },
    "meta": {},
    "request_id": "req-xxx",
    "timestamp": "2026-08-08T08:30:00Z",
    "version": "v1"
}
```

**Gagal (*Error*):**
```json
{
    "error_code": "VALIDATION_ERROR",
    "message": "Request validation failed.",
    "details": {
        "query->page": "Input should be greater than or equal to 1"
    },
    "request_id": "req-xxx",
    "timestamp": "2026-08-08T08:30:00Z",
    "path": "/api/v1/areas",
    "version": "v1"
}
```

## Batasan yang Diketahui
- Kode error domain saat ini dipetakan secara heuristik (membaca string `"Area"` atau `"Prediction"` dari pesan Error) demi mempercepat stubbing. Untuk implementasi jangka panjang seiring bertumbuhnya Entitas Domain, sebaiknya `AppException` memiliki properti bawaan `.error_code` khusus.
- Tidak ada penghapusan rute (DELETE) atau pembuatan (POST) pada Sprint ini sesuai dengan instruksi mutlak.

## Peningkatan Kedepan
- Saat ini modul siap untuk menampung *Rate Limiting*. Saat pengguna menabrak batas Rate Limit, `error_handler.py` akan siap menangkap HTTP 429 dan membungkusnya menjadi `ApiError` yang rapi.
