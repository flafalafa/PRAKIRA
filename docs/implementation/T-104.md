# T-104: Enterprise Logging & Observability Foundation

## Summary
Successfully implemented an enterprise-grade structured JSON logging foundation for Flood Guardian. The solution utilizes `ContextVars` to inject correlation IDs and request context into every log entry generated during an HTTP request lifecycle. The configuration is dynamically loaded from Pydantic settings.

## Architecture Decisions
1. **JSON Structured Logging**: Used a custom `logging.Formatter` (`EnterpriseJSONFormatter`) that converts all python log records into a strict JSON payload. This prepares the application for effortless ingestion by Loki, ELK, or Datadog without complex string parsing.
2. **ContextVars for Request Context**: Chose `contextvars` over `threading.local` for asynchronous compatibility with FastAPI, enabling `X-Correlation-ID` and contextual fields (method, URL, client IP, response time) to seamlessly appear on any downstream log call without manual passing.
3. **Sensitive Data Masking**: An interceptor function deeply crawls log metadata/`extra` arguments during formatting and masks potential secrets (keys containing "password", "token", "secret", "api_key").
4. **Log Rotation**: Built-in support for log rotation (`RotatingFileHandler`) restricted to 10MB per file with 5 backups, protecting the disk from log exhaustion.

## Known Limitations
- Application does not export OpenTelemetry metrics (traces/spans) yet, this requires the `opentelemetry` SDK which is omitted to minimize dependencies in the MVP backend foundation phase.
- File logging relies on blocking disk I/O in the Python logging library (`RotatingFileHandler`). Extremely high throughput might experience slight latency; future optimizations might consider an asynchronous log queue.
