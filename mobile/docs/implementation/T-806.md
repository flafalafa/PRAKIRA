# T-806: Enterprise Flood Dashboard

## Overview
This document outlines the implementation of the Enterprise Flood Dashboard (T-806) for the Flood Guardian mobile application. The dashboard serves as the primary citizen-facing interface, displaying real-time flood risk, predictions, and alerts based on the active area selected in T-805.

## Adherence to Constraints
- **No Local Business Logic**: The Flutter app strictly acts as a view layer. Risk scores, status levels (Safe, Watch, Warning, Danger, Emergency), and recommendations are all provided directly by the backend contract.
- **T-803 Integrity**: `PredictionRemoteDataSource` and `AlertRemoteDataSource` were refactored to use the accurate Sprint 7 backend paths (`/areas/{area_id}/prediction` and `/areas/{area_id}/alerts/active`) while maintaining full compatibility with the existing `ApiClient`.
- **T-805 Integration**: The `DashboardController` listens to the `AreaController` and automatically updates its data when the user switches areas.

## Architecture

### 1. Domain Models
- `PredictionModel` & `PredictionExplanationModel`: Mapped directly from backend `prediction.py`.
- `AlertModel` & `AlertExplanationModel`: Mapped directly from backend `alert.py`.

### 2. Repositories
- `PredictionRepository`: Coordinates fetching the current prediction for an area.
- `AlertRepository`: Coordinates fetching active alerts, handling 404s gracefully when no active alerts exist.

### 3. State Management
- `DashboardController` (`ChangeNotifier`): Manages the state of the dashboard (`DashboardStateStatus`), aggregates prediction and alert data concurrently, and handles refresh interactions. It respects partial data availability (e.g., alert fails but prediction succeeds).

### 4. User Interface
- `DashboardScreen`: The main screen that composes the dashboard.
- `DashboardRiskCard`: Displays the current risk level using `AppStatusIndicator` and shows immediate recommendations.
- `DashboardConditionsCard`: Displays key environmental conditions (Water Level, Rainfall) and Estimated Arrival Time, dynamically hiding if data is unavailable.
- `DashboardExplanationCard`: Provides transparency into the AI's decision by displaying primary risk factors and supporting observations.

## Emergency Visual Treatment
When the risk level is `EMERGENCY`:
- The `DashboardRiskCard` highlights the risk level and recommendation with `AppColors.red700` and bold typography.
- An `AppAlertBanner` with `RiskState.emergency` is prominently displayed at the top of the dashboard if an emergency alert is active.
- Emergency information always dominates secondary information visually.
